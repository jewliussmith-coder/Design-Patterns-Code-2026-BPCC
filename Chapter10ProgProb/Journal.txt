Journal:

Phase 1: Writing this program was pretty simple, but I noticed I had to use 4 conditional branches to check the guard's current state. If I added a new state, like Sleeping or Panicked, I would have to go back and edit at least 2 methods: hearNoise() and loseTarget(). This could make the code more complicated and harder to manage as more states are added.

Phase 2: The context ,SentinelGuard, is responsible for keeping track of the current state and passing actions to it. The state objects handle what happens depending on which state the guard is in. Delegating to objects is cleaner because I don't have to use a bunch of if/else statements to check the current state. If I want to add a new state, I can create another class instead of changing all the existing methods. This makes the code easier to organize and manage.
